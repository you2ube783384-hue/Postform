     1→     1→# POSTFORM — Mobile App-Like E-Commerce Experience
     2→     2→## Master Prompt for AI Web Development Agents
     3→     3→
     4→     4→> **Goal:** Build POSTFORM so the desktop experience remains a premium, conventional fashion e-commerce website, while mobile and tablet deliberately feel like a polished native shopping app.
     5→     5→>
     6→     6→> **Non-negotiable principle:** Do not simply shrink the desktop UI. Share the same data, business logic, and design system, but create a dedicated mobile/tablet interaction model.
     7→     7→
     8→     8→---
     9→     9→
    10→    10→## 1. Project Context
    11→    11→
    12→    12→POSTFORM is a streetwear-focused resale business selling whatever verified fashion inventory is acquired, including:
    13→    13→
    14→    14→- T-shirts
    15→    15→- Oversized T-shirts
    16→    16→- Shirts
    17→    17→- Hoodies
    18→    18→- Pants
    19→    19→- Jeans
    20→    20→- Sneakers
    21→    21→- Accessories
    22→    22→- Other fashion products
    23→    23→
    24→    24→The visual direction is:
    25→    25→
    26→    26→**Streetwear + Editorial Fashion + Neo-Brutalism + Premium Minimalism**
    27→    27→
    28→    28→The result must feel distinctive and brand-led, not like a generic marketplace.
    29→    29→
    30→    30→---
    31→    31→
    32→    32→## 2. Responsive Experience
    33→    33→
    34→    34→### Desktop / PC
    35→    35→

    37→    37→
    38→    38→- Full desktop header/navigation
    39→    39→- Product grids

    42→    42→- Sidebar filters where useful

    45→    45→- Product imagery as the main visual focus
    46→    46→- No persistent mobile-style bottom navigation
    47→    47→

    51→    51→

    53→    53→- Sticky bottom navigation
    54→    54→- Thumb-friendly controls
    55→    55→- Horizontal category navigation
    56→    56→- Bottom-sheet filters
    57→    57→- Swipeable product galleries
    58→    58→- Sticky purchase controls
    59→    59→- Compact checkout

    61→    61→- Safe-area support

   187→   187→## 7. Sticky Mobile Bottom Navigation
   188→   188→
   189→   189→This is a core requirement.
   190→   190→
   191→   191→On mobile and appropriate tablet layouts, create persistent bottom navigation.
   192→   192→
   193→   193→Concept:
   194→   194→
   195→   195→```text
   196→   196→┌──────────────────────────────────────┐
   197→   197→│                                      │
   198→   198→│             PAGE CONTENT             │
   199→   199→│                                      │
   200→   200→├──────────────────────────────────────┤
   201→   201→│ Home  Explore  Categories  Account  Cart │
   202→   202→└──────────────────────────────────────┘
   203→   203→```
   204→   204→
   205→   205→Recommended destinations:
   206→   206→
   207→   207→1. Home
   208→   208→2. Explore / Shop
   209→   209→3. Categories
   210→   210→4. Account
   211→   211→5. Cart
   212→   212→
   213→   213→If Wishlist is more useful than Account in the final information architecture, make that decision intelligently without overcrowding the navigation.
   214→   214→
   215→   215→Requirements:
   216→   216→
   217→   217→- Fixed/sticky to bottom
   218→   218→- Remains visible while scrolling
   219→   219→- Clear active state
   220→   220→- Large touch targets
   221→   221→- Cart quantity badge
   222→   222→- Safe-area support
   223→   223→- Must not cover content
   224→   224→
   225→   225→Use safe-area handling where appropriate:
   226→   226→
   227→   227→```css
   228→   228→padding-bottom: env(safe-area-inset-bottom);
   229→   229→```
   230→   230→

   612→   612→## 22. POSTFORM Visual Identity
   613→   613→
   614→   614→The mobile app-like behavior must remain unmistakably POSTFORM.
   615→   615→
   616→   616→### Background
   617→   617→
   618→   618→Warm milky-white / soft off-white.
   619→   619→
   620→   620→### Borders
   621→   621→
   622→   622→Strong black structural borders.
   623→   623→
   624→   624→### Typography
   625→   625→
   626→   626→Bold, editorial, highly legible typography.
   627→   627→
   628→   628→Use a technical/monospace influence selectively for labels, metadata, navigation, prices, or UI elements without harming readability.
   629→   629→
   630→   630→### Accent colors
   631→   631→
   632→   632→Controlled:
   633→   633→
   634→   634→- Yellow
   635→   635→- Purple
   636→   636→
   637→   637→Yellow can be used for strong CTAs.
   638→   638→
   639→   639→Purple should be a supporting accent.
   640→   640→
   641→   641→Do not flood the interface with color.
   642→   642→
   643→   643→### Geometry
   644→   644→
   645→   645→Use:
   646→   646→
   647→   647→- Strong rectangular structures
   648→   648→- Controlled rounding
   649→   649→- Bold borders
   650→   650→- Confident spacing
   651→   651→- Editorial composition
   652→   652→
